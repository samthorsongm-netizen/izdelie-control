# Контроль разработки и выполнения изделия

Веб-замена экселевского шаблона `Пример/6282-2103700-10_v2.xlsm`. Структура изделия — дерево сборок, у каждой
позиции свои этапы (3D, чертёж, проверка, карточка и т.д.), сроки, ответственные и прогресс.

Главное отличие от Excel: **уровней нет**. Вложенность задаётся перетаскиванием и кнопкой «+» в строке, нумерация
не нужна. Одна позиция (один номер ТС) — одна запись на всё изделие: где бы деталь ни стояла, отметки у неё общие.

## Что уже работает

- дерево изделия: добавить/переместить (drag&drop и диалог «Переместить»)/удалить (удалить всё или поднять детей);
  защита от вложения сборки в саму себя;
- 5 типов позиций с матрицей этапов как в Excel: Сборка 9, Сборка БЧ 6, Деталь 7, Деталь БЧ 4, Покупной 1;
- БЧ: у БЧ-типов вместо галки чертежа — номер документа, где лежит чертёж (групповой чертёж);
- прогресс и статус, отдельно «своя готовность» и «с детьми»;
- ответственные и сроки по 3D и чертежу, подсветка просрочки (красный) и ближайших 7 дней (жёлтый);
- количество на сборку, поставщик и номер у производителя (необязательные поля);
- поиск по номеру и наименованию с раскрытием ветки и подсветкой; бейдж «×N» — в скольких сборках стоит позиция;
- фильтры: тип, статус, «мои задачи», «просроченные»;
- KPI как в Excel: позиций, готово, в работе, не начато, просрочено, средняя готовность, 3D и чертежи «X из Y»;
- отмена последних 10 действий (кнопка «Отменить»);
- история изменений (кто/когда/что), хранение 30 дней;
- экспорт в Excel (структура с отступами + сводка) и печать/PDF из браузера;
- несколько изделий, создание с копированием структуры;
- три роли: полный доступ / отметки и поля / только просмотр;
- экран «Пользователи» для админа: добавить человека, сменить роль — без SQL.

## Структура репозитория

```
app/                     фронтенд (React + Vite + TypeScript)
  src/model/             типы, матрица этапов, дерево, прогресс (чистая логика + тесты)
  src/data/              хранилище: Supabase и демо-режим в localStorage
  src/components/        таблица, диалоги, экспорт
supabase/schema.sql      схема, права, realtime, функция копирования структуры
supabase/seed.sql        пилотное изделие 6282-2103700-10 (сгенерировано из Excel)
tools/import_xlsm.py     импорт Excel → seed.json + seed.sql
.github/workflows/       сборка и выкладка на GitHub Pages
Пример/                  исходный эксель
```

## Быстрый старт (демо, без сервера)

```bash
cd app
pnpm install
pnpm dev
```

Без переменных окружения приложение работает в демо-режиме: данные лежат в localStorage браузера, уже залито
изделие из Excel. Совместной работы, ролей и общей истории в этом режиме нет — это только для примерки.

## Подключение Supabase (общий доступ, роли, история)

1. Создать проект на supabase.com (бесплатного тарифа хватает).
2. SQL Editor → выполнить `supabase/schema.sql`.
3. При желании залить пилотное изделие: выполнить `supabase/seed.sql`.
4. Authentication → Providers → Email: **Enable sign ups** включить, **Confirm email** выключить (иначе новых
   пользователей не добавить из приложения, а им придётся подтверждать почту).
5. Создать первого администратора (Authentication → Users → Add user, пароль задать вручную) и выдать ему роль —
   один раз через SQL, дальше роли меняются в приложении:
   ```sql
   update public.profiles set role = 'admin' where email = 'ivanov@example.com';
   ```
   Остальных людей и их роли добавляет уже сам админ: кнопка **«Пользователи»** в шапке приложения.
6. Взять Project URL и anon key (Settings → API) и положить в переменные окружения.

Локально — файл `app/.env.local`:

```
VITE_SUPABASE_URL=https://xxxx.supabase.co
VITE_SUPABASE_ANON_KEY=eyJhbGciOi...
```

## Выкладка на GitHub Pages

1. Запушить репозиторий на GitHub.
2. Settings → Pages → Source: **GitHub Actions**.
3. Settings → Secrets and variables → Actions → **Variables**: добавить `VITE_SUPABASE_URL` и
   `VITE_SUPABASE_ANON_KEY` (anon key публичный, секретом не является).
4. Пуш в `main` — workflow `.github/workflows/pages.yml` соберёт и выложит сайт.

`base: './'` в `vite.config.ts`, поэтому сайт работает и в корне домена, и в подпапке `/repo-name/`.

## Перегенерация данных из Excel

```bash
python tools/import_xlsm.py
```

Читает `Пример/6282-2103700-10_v2.xlsm`, схлопывает строки с одинаковым номером ТС в одну позицию, чинит
сбитую нумерацию уровней (в исходнике `1.2.3.11` висело отдельно от своих детей `1.2.4.11.x`) и пишет
`app/src/data/seed.json` + `supabase/seed.sql`.

Текущий результат: 92 строки → 78 позиций, 92 вхождения, глубина 5 уровней, 30 позиций пока без номера ТС.

## Ограничения и что дальше

- Rename изделия (код/наименование) пока только через БД.
- Отмена работает в текущей сессии и хранит 10 шагов; после перезагрузки страницы история отмены пустая
  (журнал изменений при этом сохраняется).
- Пуш-уведомлений и напоминаний нет.
- Матрица этапов зашита в код (`app/src/model/stages.ts`); настраиваемой в интерфейсе нет.
- Если Supabase станет недоступен, данные остаются в БД — приложение просто не загрузится.
